Privacy policy

Updated October 26, 2026 · Personal application

The Daily Brief is a personal application developed and used by Henry Weil. This policy describes the current standalone Gmail collector and its public information website.

Google data accessed

With the owner’s explicit consent, the collector uses the Gmail API and the https://www.googleapis.com/auth/gmail.readonly scope. It accesses the authorized account’s Gmail profile to verify its email address, searches qualifying messages, and retrieves message identifiers, headers, senders, recipients, subjects, timestamps, labels, and full message bodies. MIME attachment metadata and links found in messages may also be recorded.

The current collection test does not download attachment contents or follow article links. Those features, if enabled later, will be described here. The source collector’s authorization does not permit sending or mailbox changes. With separate explicit consent, the delivery component requests https://www.googleapis.com/auth/gmail.send together with read-only access for the personal account. It transmits a MIME briefing, including HTML and plain-text content, to Google for delivery to the owner’s personal address. The component stores delivery identifiers and content digests locally to reconcile uncertain results and avoid blind duplicate sends. No deletion, archiving or label modifications are enabled.

Purpose and access

Data is used to develop and validate the owner’s personal email briefing: checking coverage, extracting readable message content, identifying protected messages, and auditing successful retrieval. The collector enforces its configured account identities; it is not open to other users.

Storage and retention

OAuth credentials, refresh tokens, message captures, generated drafts and operational records are stored in private folders on owner-controlled computers and the owner’s Oracle Cloud server. Credentials are separate by account and role. File permissions restrict access, but applications sharing the same operating-system user are not separate security boundaries. Private runtime files are not uploaded to this public repository, website or the owner’s synced notes vault.

The owner has approved production retention. Once the workflow is activated, completed production message-body captures, rendered payloads and recognized editorial request/log folders are eligible for removal after 14 days. Unresolved runs are retained for recovery. Delivery identifiers, content digests, coverage boundaries and source-ID audit records remain until the owner removes them. Historical development captures and older standalone test files require manual removal. Retention is deferred while a production run remains unresolved. Revoking Google access does not itself delete previously saved files.

Sharing and AI processing

The standalone collector communicates with Google for authorization and Gmail API access. With the owner’s explicit approval, a separate editorial step sends collected message headers, subjects, sender information, timestamps, account identifiers, full readable bodies, and extracted article links to OpenAI through the Codex CLI using the owner’s existing ChatGPT subscription. This content is used to classify messages and draft the owner’s private morning briefing. Gmail OAuth credentials and refresh tokens are not included in editorial input. The current test does not send attachment contents or retrieve external article pages.

Before the editorial step runs, the owner must confirm that the relevant ChatGPT model-improvement setting is off. The CLI uses an ephemeral session and the runner saves source captures and generated drafts in private owner-controlled local or Oracle-server storage. Ephemeral mode concerns local session persistence; it is not a claim of zero server retention. OpenAI processes submitted material under its applicable terms, privacy policy and account data controls. The application does not claim a fixed server-retention period or enterprise Zero Data Retention for a personal subscription. See OpenAI’s data controls guidance.

The application does not sell Google user data, use it for advertising, or use it to train generalized AI models. The Daily Brief’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Removing access and data

The owner can revoke The Daily Brief’s access from Google Account connections and permissions. The owner can also stop the collector and remove its private local token and data files.

This public website

This static information site contains no login, tracking scripts, analytics, or advertising. GitHub Pages hosts it and may record visitor IP addresses for security under GitHub’s privacy statement. The website does not receive mailbox data or OAuth callbacks.

Changes and contact

This policy will be updated before material changes to data access, external processing, retention, or hosting. Contact the developer at hbweil9@gmail.com.
